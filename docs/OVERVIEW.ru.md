## 1. Что это и для кого

**White-label SaaS для ипотечных брокеров США, которые выдают DSCR-кредиты** — кредиты на инвестиционную недвижимость, где заёмщика оценивают по аренде объекта, а не по его доходу. DSCR = аренда / платёж (PITIA).

Три уровня пользователей:

| Кто | Что делает в продукте |
|---|---|
| **Агентство** (владелец платформы) | Продаёт продукт брокерам, заводит их, включает модули, видит использование и отток |
| **Брокер** (компания) и его **лоан-офицеры (LO)** | Получают свой бренд, свои публичные страницы, лиды, сценарии, базу закрытых кредитов |
| **Инвестор** (клиент брокера) и **риелтор** (партнёр) | Пользуются публичными страницами без регистрации |

Каждый брокер изолирован: свои цвета, логотип, NMLS, штаты, тема оформления, лиды и интеграции. Данные одного брокера другому недоступны (это покрыто тестами).

## 2. Пять модулей

### Модуль 1. DSCR Instant Check — публичный калькулятор
- Адрес: `/b/[slug]/check` + встраивание одной строкой на сайт брокера (`/embed.js`).
- Покупка или cash-out рефинанс. Инвестор вводит цену, аренду, первый взнос, кредитный рейтинг.
- Результат: DSCR, вердикт ("Looks strong / Borderline / Needs adjustment / Not eligible under current defaults"), платёж, нужные деньги на сделку, максимальная сумма кредита.
- **"What to change"** — что поменять, чтобы сделка прошла: на сколько поднять аренду, увеличить взнос, снизить цену или выкупить ставку.
- За PDF-оценку инвестор оставляет контакты (согласие TCPA, защита от ботов). Дальше: лид в CRM, письмо брокеру, подписанный webhook в его CRM (Zapier/Make).

### Модуль 2. Scenario Sheet — сравнение вариантов кредита
- LO собирает 2–3 варианта (продукт, ставка, баллы/кредит, комиссии, штраф за досрочное погашение) и отправляет клиенту приватную ссылку `/b/[slug]/s/[token]` + PDF.
- Трекинг: открытия, время на странице, какие варианты клиент раскрывал.
- LO получает письмо при первом открытии и при возврате через 24 ч+.
- Кнопка "I'm interested in Option B" + вопрос клиента. Срок жизни 30 дней, ссылку можно отозвать.

### Модуль 3. Money List — деньги в уже закрытых кредитах
- Импорт закрытых кредитов из LOS через CSV: сопоставление колонок, валидация, дедупликация, повторный импорт обновляет записи.
- Ежедневная проверка поводов связаться: окончание штрафа за досрочное погашение, seasoning 6/12 месяцев, падение ставок, пересмотр ARM, годовщины.
- Список отсортирован по оценке чистой выгоды для клиента.
- AI-черновики письма и SMS; compliance-футер добавляется кодом, а не моделью.
- Статусы: contacted / snooze / not interested / won. Ежемесячный дайджест.

### Модуль 4. Listing Snapshot — флаер для риелтора
- Одностраничный co-branded флаер на объект риелтора (2 шаблона).
- Платёж, DSCR, денежный поток и деньги на сделку при 20% и 25% взноса; аренда, нужная для DSCR 1.00 и 1.20.
- QR-код ведёт на живую страницу объекта `/l/[token]` с формой заявки на финансирование.
- Статистика по каждому риелтору и письмо со статистикой. Пометка RESPA о совместном маркетинге.

### Модуль 5. Notes-to-Scenario — из заметок звонка в сценарий
- LO вставляет заметки, письмо или расшифровку разговора.
- Claude извлекает параметры сделки в строгую схему. LO проверяет; до подтверждения ничего не сохраняется.
- Одним кликом: черновик сценария, список документов под эту сделку и письмо-фоллоу-ап.
- Без API-ключа работает правиловый парсер.

### Плюс
- **Leads CRM-lite:** статус, ответственный, заметки, согласия, лента событий, экспорт CSV, удаление по CCPA.
- **ROI:** еженедельное письмо брокеру о том, что принёс продукт.
- **Админка агентства:** создание брокеров через мастер онбординга, флаги модулей, приглашения команды, вход от имени брокера с журналом аудита, использование и сигналы оттока, ежемесячная сводка.

## 3. Раскладка: какие экраны есть

### Публичные (без входа)
| Страница | Назначение |
|---|---|
| `/b/[slug]/check` | Калькулятор Instant Check в бренде брокера |
| `/embed/check` + `/embed.js` | Тот же калькулятор внутри сайта брокера |
| `/b/[slug]/s/[token]` | Сценарий для клиента (варианты кредита) |
| `/l/[token]` | Страница объекта риелтора с формой |

На каждой публичной странице, в PDF и письме есть футер брокера: оба NMLS ID, лицензированные штаты, дисклеймер, Equal Housing Opportunity.

### Кабинет брокера `/dashboard`
- **Overview** — сводка: лиды, сценарии, деньги в Money List, ROI.
- **Leads** — список, карточка лида, создание.
- **Money List** — доска возможностей, карточка кредита, импорт CSV, полный список.
- **Scenarios** — список, создание, просмотр, редактирование.
- **Snapshots** — флаеры: список, создание, просмотр.
- **Notes** — Notes-to-Scenario.
- **Share** — ссылки и код встраивания.
- **Settings** — Branding, Appearance (выбор темы с живым превью), Team, Program (параметры кредитной программы), States, Compliance, Integrations (webhook).

### Админка агентства `/admin`
Обзор (с темой по умолчанию), брокеры (с переопределением темы), журнал аудита. Мастер `/onboarding`.

### Для разработки
`/dev/mailbox` — все письма без реальной отправки. `/dev/design` — галерея всех экранов во всех темах.

## 4. Дизайн: три переключаемые темы

У каждого брокера одна из трёх тем, переключается в Settings → Appearance. Тема применяется ко всему: публичные страницы, embed, кабинет, PDF и письма.

| Тема | Характер |
|---|---|
| **maison** | Спокойная, «банковская», с засечками — доверие и солидность |
| **terminal** | Плотная, моноширинная, «как Bloomberg» — для цифровых инвесторов |
| **atelier** | Светлая, редакционная, воздушная — премиальный бутик |

- Акцентный цвет брокера автоматически подгоняется до контраста AA (OKLCH).
- Шрифты своего хостинга, без внешних запросов.
- Тема меняет только шесть компонентов (главная цифра результата, шкала покрытия, бейдж вердикта, сравнение вариантов, список улучшений, оболочка кабинета). Всё остальное работает через семантические токены.
- Lighthouse mobile: производительность 94–97, остальные категории 100. Проверка axe чистая во всех темах.

## 5. Workflow: как этим пользуются

### Инвестор
1. Заходит на сайт брокера → открывает калькулятор.
2. Видит DSCR, вердикт и что поменять.
3. Оставляет контакты → получает PDF-оценку на почту.
4. Позже получает от LO ссылку на сценарий → сравнивает варианты → жмёт "I'm interested".

### Лоан-офицер
1. Получает письмо о новом лиде (и webhook в CRM).
2. После звонка вставляет заметки в Notes → проверяет извлечённые данные → создаёт сценарий.
3. Отправляет клиенту ссылку на сценарий → видит, когда клиент открыл и что смотрел.
4. Раз в день смотрит Money List → берёт AI-черновик письма/SMS → связывается с прошлым клиентом → отмечает результат.
5. Делает флаер для знакомого риелтора → риелтор раздаёт QR → входящие лиды с объекта.

### Брокер (админ компании)
Настраивает бренд, тему, штаты, программу, compliance-тексты, команду и интеграции. Получает еженедельный ROI и ежемесячный дайджест.

### Агентство
Заводит брокера через мастер → включает модули → следит за использованием и оттоком → при поддержке входит от имени брокера (с записью в аудит).

### Разработка
- Запуск: `npm install` → `npm run setup` → `npm run dev`. На `/login` есть демо-аккаунты в один клик.
- Работает **без единого API-ключа**: у каждой интеграции (почта, Claude, RentCast, Turnstile) есть рабочая заглушка.
- CI на каждый push: lint (запрещённые слова, деньги только в движке, изоляция тенантов) → typecheck → 75 unit-тестов → 22 e2e Playwright на production-сборке (мобильный + десктоп).

## 6. Правила, на которых всё стоит

- **Вся денежная математика — только в движке `lib/dscr`**: целые центы, DSCR округляется вниз, golden- и property-тесты. Интерфейс только форматирует.
- **Compliance:** запрещённые слова (approved, pre-approved, pre-qualified, qualifies, guaranteed, commitment) ловятся линтером в UI, PDF, письмах и AI-черновиках.
- **Изоляция данных:** все запросы к данным брокера идут через `forBroker(brokerId)`.
- **Безопасность:** публичные токены по ~138 бит, webhook подписан HMAC с повторами, rate limit и honeypot на формах. Нет SSN, документов и аудио; в демо-данных нет реальных людей и компаний.
